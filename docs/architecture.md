# Architecture

## Goal

A season dashboard, available online, that stays current on its own: agents run before each week starts (and ideally mid-week) to research waivers, injuries, and matchups, and to monitor how the league and season are going.

## Pieces

### 1. Data layer — Yahoo Fantasy read API
Read-only OAuth pull of the league: transactions, all rosters, free agents, weekly
lineups, matchups/standings. Details and confirmed capabilities live in
[yahoo-api.md](yahoo-api.md). Pulls run on a schedule and land as JSON snapshots in
`data/` (and/or a hosted KV/D1 store), so the dashboard and agents read from the
same source of truth.

### 2. Dashboard — hosted web app
Season overview: standings, this week's matchups, recent transactions ticker,
waiver-wire watch list, my roster with sit/start notes, league power rankings.

Hosting candidate: **Cloudflare Workers** (already connected here — Workers + KV/D1
for storing pulled snapshots, a cron trigger for refreshes). Alternative: static
site on GitHub Pages regenerated by scheduled runs. Decision pending.

### 3. Agents — scheduled research runs
Claude Code scheduled tasks (cron) that run per-week:

| Agent | When | Job |
|---|---|---|
| Waiver scout | Tue night (after MNF, before waivers clear) | Cross-reference league free agents vs. drops, injuries, usage trends; produce ranked claim targets |
| Sit/start analyst | Thu morning + Sun morning | Matchup analysis for my roster; flag risky starters, recommend swaps |
| League monitor | Daily in-season | Diff league transactions/rosters since last pull; summarize rival moves |
| Week recap | Tue morning | Scoreboard recap, standings shift, luck analysis, looking-ahead notes |

Agent output goes into `data/reports/` and feeds the dashboard.

## Open decisions

- Dashboard stack (Workers app vs. static regeneration) — decide after first data pull proves out.
- Where tokens live for unattended runs (local cron on this machine vs. Worker secret).
- Non-Yahoo data sources for projections/news (FantasyPros, nfl_data_py, Sleeper) — pending API research.
